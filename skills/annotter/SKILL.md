# Annotter AI Assistant Skill

This skill guides AI coding agents (Claude Code, Cursor, Antigravity, Codex) in interpreting and resolving structured visual UI feedback generated by **Annotter** in Flutter apps.

---

## What is Annotter?

Annotter is a pure-Flutter, in-app visual feedback tool that turns runtime UI taps into rich, structured context. 

When a user annotates their Flutter app, Annotter generates markdown reports containing:
- **Target Widget & Hierarchy:** e.g., `HomeScreen > ActionCard > AppButton > Text`
- **Text Content:** Exact string inside the element, e.g., `Content: "Submit Request"`
- **Intent & Severity:** `[FIX]`, `[STYLE]`, `[CHANGE]`, `[QUESTION]` | `[BLOCKING]`, `[IMPORTANT]`, `[SUGGESTION]`
- **Position & Screen Route:** Screen name, route path, pixel coordinates, viewport, and theme mode.

---

## How to Process Annotter Feedback

When the user pastes an Annotter report or asks to "fix UI annotations", follow this systematic workflow:

### Step 1: Prioritize by Severity & Intent
Order the tasks:
1. `[BLOCKING]` + `[FIX]` (Broken functionality / layout overflow)
2. `[IMPORTANT]` + `[CHANGE]` (Logic / behavior changes)
3. `[STYLE]` + `[SUGGESTION]` (Padding, alignment, color, typography tweaks)

### Step 2: Locate Code Using the 3 Fast Anchors
Do NOT guess file locations. Use the rich metadata provided:
1. **Anchor 1: Text Content (`Content: "..."`)**
   * Run grep directly on the string:
     ```bash
     git grep "Exact Text Here"
     ```
   * This instantly gives you the exact file and line number in < 1 second.
2. **Anchor 2: Custom Component Name (`widgetName`)**
   * Grep for the widget class definition:
     ```bash
     git grep "class AppButton"
     ```
3. **Anchor 3: Breadcrumb Tree (`Tree: ParentScreen > Card > Component`)**
   * Identifies where the child component is instantiated within its parent page.

### Step 3: Implement the Requested Changes
- Keep changes minimal and focused directly on the user's note.
- Respect existing design tokens, theme data (`Theme.of(context)`), and responsiveness.
- If the report indicates a mobile viewport (e.g. 390x844), ensure the layout doesn't overflow on smaller screens.

### Step 4: Verify & Report
1. Run `flutter analyze` to ensure zero compilation or lint errors.
2. Run `flutter test` to ensure existing regression tests pass.
3. If connected to Annotter MCP Server, call `annotter_resolve_annotation(id, message)` to turn the user's screen pin into a green checkmark (`✓`).
4. Provide a concise bullet-point summary to the user referencing each annotation number.

---

## MCP Server Interaction (Optional)

If the project is configured with the Annotter MCP server:
- **`annotter_get_pending_annotations()`**: Fetches all live unresolved annotations from the running Flutter app.
- **`annotter_resolve_annotation(id, message)`**: Marks an annotation as fixed and updates the device screen in real time.
- **`annotter_clear_all()`**: Clears the session once all items are completed.
